# QuickBooks integration + financial narrative digest — Phase 1 spec

## Goal
Connect Aervo to QuickBooks Online so the Intelligence Center can combine operational data (Shopify/Square) with financial data (QuickBooks) to show true margin per product and generate a plain-language weekly digest for the business owner.

## Repo
`aervo-backend` — follow the existing factory pattern: every new route file exports `module.exports = function(pool, authenticateToken) {...}` and must be explicitly mounted in `index.js`.

---

## Phase 1 scope

1. QuickBooks OAuth connection
2. QuickBooks data sync (nightly job)
3. SKU mapping table (Aervo product ↔ QuickBooks item)
4. Manual SKU mapping UI (backend routes — frontend to follow in `aervo` repo)
5. Margin calculation with fallback estimate
6. Weekly narrative digest generation (cached, reuses existing Claude/Anthropic SDK pattern from Smart Playbooks)

Out of scope for phase 1: two-way sync back to QuickBooks, cash flow forecasting, QuickBooks Desktop (Online only).

---

## 1. QuickBooks OAuth

- Use QuickBooks Online API, OAuth 2.0.
- New route file: `routes/quickbooks/auth.js`
  - `GET /api/quickbooks/connect` — redirects to Intuit's OAuth consent screen
  - `GET /api/quickbooks/callback` — exchanges code for access/refresh tokens, stores them
  - `POST /api/quickbooks/disconnect` — revokes and clears stored tokens
- New env vars needed: `QUICKBOOKS_CLIENT_ID`, `QUICKBOOKS_CLIENT_SECRET`, `QUICKBOOKS_REDIRECT_URI`, `QUICKBOOKS_ENVIRONMENT` (sandbox/production)
- Store tokens in a new `quickbooks_connections` table (see schema below), scoped per Aervo account, not globally — same multi-tenant pattern as the Shopify/Square integrations.

## 2. Nightly sync job

- New file: `scripts/sync-quickbooks.js` (follow the pattern of existing scripts in `/scripts`)
- Pulls:
  - Items (Product/Service list) — for SKU matching
  - Purchases/Bills — for cost data where item-level detail isn't directly on the Item record
  - P&L summary — for category-level fallback margin estimates
- Refreshes OAuth token if expired before syncing.
- Writes results into `quickbooks_items` and `quickbooks_purchases` staging tables (raw-ish, lightly normalized) — don't overwrite `products` directly.

## 3. SKU mapping table

New table: `product_cost_mappings`

| column | type | notes |
|---|---|---|
| id | uuid | pk |
| account_id | uuid | fk, which Aervo account this belongs to |
| aervo_product_id | uuid | fk to existing products table |
| quickbooks_item_id | text | nullable — null until matched |
| match_type | text | `auto`, `manual`, or `unmatched` |
| created_at, updated_at | timestamp | |

Auto-match logic (runs after each sync): compare `products.sku` to `quickbooks_items.sku` (case-insensitive, trimmed). Exact matches get `match_type = 'auto'`. No match → row still created with `quickbooks_item_id = null`, `match_type = 'unmatched'`, so the mapping UI has something to display.

## 4. Manual mapping — backend routes

New route file: `routes/products/cost-mapping.js`

- `GET /api/products/cost-mapping` — returns all products with their current mapping status (matched/unmatched) and, if unmatched, a list of QuickBooks items to choose from
- `POST /api/products/cost-mapping/:productId` — body: `{ quickbooks_item_id }`, sets `match_type = 'manual'`
- `DELETE /api/products/cost-mapping/:productId` — clears a mapping, reverts to unmatched

(Frontend for this — a table with dropdowns — is a separate task in the `aervo` repo once these routes exist.)

## 5. Margin calculation

New route file: `routes/analytics/margin.js`

- `GET /api/analytics/margin?period=week` — for each product sold in the period:
  - If mapped (auto or manual): cost = QuickBooks item cost, or average cost from linked Purchases/Bills if no direct cost field
  - If unmatched: cost = category average from the P&L pull (mark this result `estimated: true` in the response so the frontend can visually flag it as an estimate, not a hard number)
- Returns per-product: revenue, cost, margin %, and whether the figure is estimated
- Cache the computed result in a new `margin_snapshots` table, one row per account per period, regenerated by the nightly sync — don't compute live on every request.

## 6. Weekly narrative digest

New route file: `routes/intelligence/digest.js`

- Reuses the existing Anthropic SDK setup already in the Intelligence Center code.
- `GET /api/intelligence/digest?period=week` — if a cached digest exists for the current period, return it; otherwise generate:
  1. Pull `margin_snapshots` for the period plus prior period for comparison
  2. Prompt Claude with the structured margin data, ask for: one headline sentence (what happened), 2-3 supporting bullets (why), grounded only in the numbers provided
  3. Cache the result (new `digests` table: `account_id`, `period`, `headline`, `body`, `generated_at`)
- Follow the same caching-over-recomputation pattern as Smart Playbooks — never call Claude fresh on every page load.

## Suggested build order for Claude Code

1. DB migrations for all new tables
2. QuickBooks OAuth routes + token storage
3. Sync script (items, purchases, P&L)
4. Auto-matching logic + mapping backend routes
5. Margin calculation route + caching

Test each stage against a QuickBooks sandbox account before moving to the next.
